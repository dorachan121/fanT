# 07. 技術動向

## 1. 加工カメラアプリに必要な技術要素

| 要素 | 内容 | 実現手段の例 |
|---|---|---|
| カメラ制御 | プレビュー、撮影、前後カメラの切り替え、露出・フラッシュ、動画 | iOS: AVFoundation / Android: CameraX |
| リアルタイムのフィルター | LUT（色変換）、粒子、光漏れ、ビネット、にじみ、色収差、日付印字 | GPU シェーダー（Metal / Core Image / OpenGL ES / Vulkan） |
| 顔検出・ランドマーク | 顔の位置・特徴点 | Apple Vision、Google MediaPipe Face Landmarker、ML Kit |
| 美肌・補正 | 肌の平滑化、トーン補正、目・輪郭の微調整 | 肌マスクと周辺の構造を保つぼかし（バイラテラル / ガイデッドフィルター）、または商用 SDK |
| セグメンテーション | 人物・背景・髪・肌の分離 | Vision（人物セグメンテーション）、MediaPipe |
| AR エフェクト | 顔に追従するスタンプ・キャラ化 | ARKit Face Tracking、商用 AR SDK |
| 後から編集 | 撮影後のフィルター変更・調整・デコ | 撮影時と同じシェーダーパイプラインを再利用する |
| 生成 AI（任意） | AI 変身・高画質化 | サーバー API、または端末上の軽量モデル |

## 2. 商用の美顔・AR SDK

| SDK | 特徴 | 注意点 | 出典 |
|---|---|---|---|
| Banuba Face AR | 112点のランドマーク、顔のパーツごとのセグメンテーション、メイク、手のトラッキング。iOS / Android / Unity / Web 対応。料金はプラットフォームごとの定額で、ユーザー数に連動しない | 比較情報は Banuba 自身のブログ由来（宣伝寄り）。2019年の中位 Android でメイクフィルター 35〜40fps（自社発表） | S-73, S-74 |
| DeepAR | 顔エフェクト・マスクが中心。68点のランドマーク | **2025年4月に Zalando が買収**し、EC 向けの方針に組み込まれた。将来の方針にリスクあり | S-74 |
| Perfect Corp（YouCam） | メイク・美容向けの AR・AI | 料金は未確認（要見積） | S-73 |
| Google MediaPipe | 顔ランドマーク・セグメンテーションのオープンソース | 美肌処理などの「見た目の品質」は自分で実装する必要がある | — |
| Apple Vision / ARKit | 標準 API で追加費用がかからない。顔ランドマーク・人物セグメンテーション・顔トラッキング | iOS 専用。ARKit の顔トラッキングは TrueDepth 対応端末に限られる | — |

**判断の目安**
- 初期は **Apple Vision と自前のシェーダー**（標準 API で費用ゼロ）で「レトロフィルター＋自然な美肌」を作れます。
- キャラ化の AR エフェクトに本格的に取り組む段階で、商用 SDK を検討します（費用と効果を見て判断）。

## 3. クロスプラットフォームとネイティブの比較

| 方式 | 長所 | 短所 |
|---|---|---|
| **iOS ネイティブ（Swift + AVFoundation + Metal）** | 最高の性能と画質。最新の API（カメラ、Vision、Core ML）を最大限に使える | iOS のみ |
| Flutter | UI を共通化できる。Flutter 自体の iOS 描画は Metal 化されている [S-75] | カメラのフレームを Dart 側に渡すと遅延・メモリ負荷が大きい [S-76]。映像処理はネイティブ側に残し、テクスチャを共有する設計が必要 |
| React Native | UI を共通化できる。VisionCamera 等の資産がある | 映像処理はネイティブのプラグインに依存する |
| Kotlin Multiplatform | ロジックを共通化し、UI と映像処理はネイティブにできる | 学習コストがかかる。iOS 側は Swift の実装が必要 |

**判断の目安**
- ターゲットの iPhone 比率は約85%（[03](03-user-trends.md)）で、カメラアプリでは**映像処理の性能が体験の質を決めます**。
- **MVP は iOS ネイティブで作ることを推奨**します。Android 対応は、需要を確認してから、映像処理の層（シェーダー・LUT）を流用できる形で進めます。
- 参考値: Apple のサンプルでは、Metal による画像処理は iPhone 6 でも CPU 1.1ms・GPU 2.6ms/フレームでした [S-77]。最近の端末なら、1080p のリアルタイムフィルターは十分に現実的です。

## 4. フィルム・デジカメ質感の作り方（技術メモ）

| 質感 | 技術 |
|---|---|
| 色味 | 3D LUT（.cube）。フィルムやデジカメの種類ごとに作る |
| 粒子 | 輝度に応じたノイズ（フレームごとに変化させる） |
| 光漏れ | 画像テクスチャの加算合成。撮影ごとにランダム化する |
| CCD のにじみ・ブルーム | 明るい部分を抽出し、ぼかして加算する |
| 低画素・ガラケー画質 | 縮小・拡大、JPEG ブロックノイズ、シャープネスの調整 |
| 色収差・ビネット | RGB のずらし、周辺の減光 |
| 日付印字 | 7セグメント風フォントの描画と、オレンジの発光表現 |
| フラッシュ | 中心の露出を上げ、周辺を落とし、背景を暗くする |
| VHS | 走査線、色ずれ、トラッキングノイズ、タイムスタンプ |

→ これらは**データ（LUT・テクスチャ・パラメーター）として定義できる**ので、アプリを更新しなくても新作フィルムを配信できる設計にできます（コンテンツの入れ替え運用と相性が良い）。
